在 PowerShell 中执行：

```powershell

# 打开交互式三维窗口，场景可选 level / upstairs / downstairs
& E:\miniconda\envs\pytorch\python.exe E:\reasearching\hip_exo\run.py --mode upstairs --viewer

# 验证模型、传感器坐标、关节范围、扭矩限制并生成三场景预览
& E:\miniconda\envs\pytorch\python.exe E:\reasearching\hip_exo\validate.py

# 修改助力幅度和相位偏移，独立保存实验
& E:\miniconda\envs\pytorch\python.exe E:\reasearching\hip_exo\run.py --mode level --amplitude 2 --phase-shift 0.05 --out E:\reasearching\hip_exo\experiment_01
```

直接加载 `outputs/level.xml`、`upstairs.xml`、`downstairs.xml` 可检查结构；**步态和助力控制在 Python 中，单独打开 XML 不会自动行走**。XML 中骨盆初值为零，交互展示须从 run.py 启动。

## 模型范围与构成

这是一个**带外部骨盆支撑、跟踪合成步态的矢状面动力学原型**，不是已验证的自主平衡人体数字孪生。可以测试 IMU 输出、控制软件、助力波形与机械功方向；不能直接推断代谢下降、临床效果、真实人体肌力或最佳助力时间。

模型包含骨盆/合并躯干和双侧大腿、小腿、足。共 9 自由度：骨盆前后/上下/俯仰 3 个，双侧髋/膝/踝各 1 个。未建模侧向平衡、髋外展、膝内外翻、软组织或肌肉。身高决定腿段长度（大腿和小腿均为身高的 0.245 倍）；上身用简化刚体表示，不是完整等比例人体扫描。

人体质量分配：躯干 52.8%、骨盆 15%、每侧大腿 10%、小腿 4.65%、足 1.45%。这些是工程近似，不是受试者测量值。另加每台电机假设质量 0.6 kg、每侧连接杆 0.15 kg，合计模型运动部分 71.5 kg；电机尺寸、质量和连接杆惯量待实物确认。

两个电机输出轴与髋屈伸轴理想同轴；输出扭矩直接作用于大腿相对骨盆的髋关节，gear=1 表示已经使用减速器**输出端**扭矩，不再乘一次减速比。两侧共用“屈髋为正”的解剖方向。电机外壳固定于骨盆两侧，连接杆随大腿运动。刚性连接忽略绑带滑移与轴线错位。

世界坐标：x 向前、y 向左、z 向上。髋屈曲绕 -y，膝屈曲绕 +y。IMU 位于每条大腿前方 6.5 cm、髋下方约 20.6 cm；传感器坐标默认与大腿一致。橙色方块为 IMU，黑色圆柱为电机。

## 电机与传感器参数出处

| 参数 | 当前设置 | 依据/状态 |
|---|---:|---|
| 电机额定、峰值输出扭矩 | 4、11 N·m | [达妙 DM-J6006-2EC 官网](https://www.damiaokeji.com/index.php?c=show&id=102) |
| 默认助力峰值 | 3 N·m | 实验假设，可改 0–4 N·m |
| 扭矩一阶滞后、变化率 | 20 ms、80 N·m/s | 工程假设，非厂家标定 |
| IMU 加速度量程 | ±6 g | [维特 HWT905 官网](https://wit-motion.com/HighprecisionTilt/39.html)，待核对实际硬件版本 |
| IMU 角速度量程 | ±2000 °/s | 同上 |
| IMU 输出频率 | 100 Hz | 仿真选择；官网标称最高 200 Hz |
| 加速度白噪声标准差 | 1.2 mg | 参考官网 100 Hz 带宽 RMS 指标；未复现完整带宽滤波 |
| 陀螺白噪声标准差 | 0.001 rad/s | 官网范围内的仿真假设 |
| 姿态噪声、常值偏差 | 0.3°、0.5°标准差 | 动态仿真假设，不等于官网静态精度 |
| 通信/融合总延迟 | 20 ms | 假设，可配置 |

用户提供的[语雀规格书](https://wit-motion.yuque.com/wumwnr/docs/szw9y6?singleDoc)在本次访问中未成功读取；采用上述厂商网页作为暂定来源，未声称核对了指定规格书。实际版本的量程、通信速率和安装轴向应据实物及规格书更新。

IMU 的原始 accelerometer/gyro 来自 MuJoCo 动力学，包含安装位置引起的运动效应；加速度计输出是比力，静止时幅值约 g，并非“已经去重力的线加速度”。姿态通道采用真实 site 四元数叠加误差的 AHRS 替代模型，**没有实现 HWT905 内部融合算法**。原始磁场传感器已定义，控制器不使用其输出；电机磁干扰、温漂、量化及软组织伪影尚未建模。[MuJoCo 传感器与 MJCF 说明](https://mujoco.readthedocs.io/en/stable/XMLreference.html)。

当前控制器额定扭矩内限幅，XML 额外保留 ±11 N·m 峰值限幅。未标定扭矩-速度包络、反电动势、电流/电压限幅、热模型和峰值持续时间，所以不能把 XML 的 11 N·m 当作可持续助力能力。没有实现 CAN 通信。

## 助力时机与方式

场景由 `--mode` 显式提供，**没有宣称用双 IMU 自动识别地形**。控制器使用延迟后的双大腿 IMU 姿态与角速度；下楼阻尼额外使用电机编码器速度（与电机现有反馈能力一致）。骨盆状态、接触信息和参考轨迹仅供虚拟人体控制与评估，不输入外骨骼相位估计。

相位估计使用滚动窗口的角度中心和 `atan2(-角速度/标称角频率, 大腿角度-中心)`，相位零点近似对应最大大腿前摆。它**不是经过验证的足跟着地相位**。默认前 1 个周期（2.4 s）收集数据不助力；摆幅不足 8°时关闭目标助力。静止/不规则步态、转弯、步速突变和模式切换未经过真实数据验证。

| 场景 | 候选策略 | 当前相位窗口（非足跟着地百分比） |
|---|---|---|
| 平地 | 后摆伸髋辅助，前摆屈髋辅助 | 0.02–0.38：负扭矩；0.55–0.95：正扭矩 |
| 上楼 | 伸髋与摆腿屈髋辅助 | 同上；默认屈髋幅值系数 0.65 |
| 下楼 | 速度反向的髋关节阻尼 | 0.02–0.45，最大 1.5 N·m |

窗口内采用 sin² 平滑脉冲，再经过执行器滞后和变化率限制。下楼重点检验负机械功；因滞后，速度反转附近可能有少量正功。髋部阻尼不能代替膝关节对下楼负功的作用。上述窗口只是可运行初值，并非文献验证或优化后的结论。

## 数据和研究使用方式

`outputs/*_assist.csv` 与 `*_baseline.csv` 分别对应有助力和无助力。包含时间、两侧 IMU 比力/角速度/俯仰、相位、髋角、角速度、人体控制器髋扭矩、电机扭矩、机械功率、接触数量和骨盆支撑力/力矩。SI 单位：m、s、rad、N、N·m、W。启动时尚无延迟 IMU 数据的字段为 NaN，是有意标记，非模拟失败。

`*_summary.json` 给出扭矩 RMS、正负机械功和跟踪误差；积分按记录频率近似，包含启动段。`comparison.png` 绘制三种场景 IMU、扭矩和功率；基线保存在单独 CSV，图中左右曲线表示双腿，不是有/无助力对照。`config_used.json` 保存运行参数。重复实验请使用不同 `--out` 目录，默认目录会覆盖。

虚拟人体通过逆动力学和反馈跟踪维持运动，其广义力施加于骨盆与所有关节，**不是额外电机硬件**。骨盆支撑力通常很大，模型允许近乎悬吊式行走，不能从人体控制器扭矩的变化直接计算“真人省力率”。脚有碰撞，支撑期脚底参考位置保留约 2 mm 间隙；接触不是承重的唯一来源。合成足轨迹采用抬脚-前移-落脚过程，尤其楼梯步态较保守，不能代替受试者运动捕捉。

推荐研究顺序：先用本工程检查轴向、延迟、波形和扭矩饱和；再导入三种状态下的双 IMU 和电机编码器同步实测数据，校准相位及分类器（保留 unknown 状态）；用运动捕捉/足底力作为离线真值验证，而非偷加到实时传感器输入；最后替换合成轨迹、标定人体/电机参数，降低虚拟支撑依赖，再比较多种相位偏移与幅度。双大腿 IMU 无法直接观测骨盆姿态、真实足底接触或唯一确定楼梯高度，这些可观测性限制应保留在论文假设中。

## 文件

- `config.json`：人体、台阶、电机和 IMU 参数。
- `model.py`：MJCF 生成、三场景与合成步态逆运动学。
- `control.py`：传感器采样/误差/延迟、相位与助力。
- `run.py`：动力学闭环、交互显示、CSV/图表。
- `validate.py`：物理约定与软件限制验证、模型预览。
- `outputs/`：生成的 XML、图、CSV 和汇总。
